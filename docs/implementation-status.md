## Deliberate implementation differences from the plans

- **Express replaces NestJS for the HTTP layer.** The environment's registry restrictions made NestJS unavailable, while Express was cached. Domain services and SQL transactions remain separate and reusable.
- **One web application provides role-specific workspaces.** Staff requests enforce backend authorization, but the operations UI is not yet a separately deployed, independently authenticated application.
- **PGlite provides the default single-process local PostgreSQL runtime.** A separate PostgreSQL adapter is also implemented. Redis, a managed queue, cloud hosting and managed database provisioning have not been introduced.
- **Private storage and evidence processing now have local and S3-compatible adapters.** Migration 011 adds scoped image/PDF originals, fail-closed ClamAV scanning, independent content review, managed artwork derivatives and retention controls. Default artwork preserves the embedded demo path; S3 mode enables the managed pipeline for new uploads. Actual bucket/scanner acceptance, independent off-host restoration, approved moderation/retention policies, large uploads and CDN deployment remain outstanding. Neither artwork nor evidence upload proves physical authenticity or legal rights.
- **Identity adapters are configurable, with local demo login retained.** Item 2 adds OIDC code/PKCE sign-in, encrypted email-link delivery, verified invitation acceptance, authenticator MFA/recovery, consented owner transfer and independent staff administration. Hosted IdP/email acceptance, account linking, deprovisioning and recovery when all factors are lost remain outstanding. KYC and age verification are not claimed. Optional Express test onboarding is separate under item 3. PostgreSQL can use separate nonowner API/worker roles with initial tenant policies; owner-mode PGlite remains the development default.
- **VIA certificates expose stored assessment validity separately from signature trust.** The item 6 increment adds independently provisioned public keys, offline certificate/checkpoint signing, Merkle proofs and a separate archive with fork protection. Managed key custody, trusted timestamps, independently administered immutable object retention and C2PA conformance remain unimplemented.
- **The outbox worker runs alongside the API.** It processes in-app notifications and reservation expiry. Identity email delivery has a separate bounded loop and configurable provider; separate worker deployments, broader notification providers, DLQs and event replay tooling remain future work.
- **SaaS billing is a separately enabled Stripe test capability.** Independently approved immutable plan versions, hosted subscription checkout, bounded trial/grace entitlements, provider invoice records and included-usage limits are implemented. Plans do not grant membership or permissions. Live billing, metered overage charges, tax/revenue accounting and payment-method portal integration remain unimplemented.
- **OpenAPI is generated from route/input definitions.** Shared response schemas/types cover organization lists, invitations, membership administration, RePool terms/offers, payment/refund status and the finance payment queue. Item passports have a validated shared schema. Every HTTP error includes code, message, field errors, retryability and a matching correlation header. Legacy response schemas and a fully generated client remain to be expanded.

## Simulated commercial boundaries

Item 1 now has a [versioned commercial decision register and local pilot approval controls](commercial-policy.md), implemented by migration **014**. Operations → Commercial covers all seven decision areas, preserves the existing demo terms and 18+ baseline, and requires a different current finance reviewer for every approved change. Proposals retain immutable evidence references, expire after seven days and fail if their base version is superseded. Local review never marks contracts, tax treatment or production jurisdiction launch approved.

Supported actions pause/restore PixUP-owned credit redemption or new pilot checkout. Approved versions invalidate uncommitted quotes; web and channel orders retain immutable quoted commercial snapshots. Committed payment/refund/replay recovery remains available. Historical records are not backfilled with invented assent or approvals. Tax computation, creator entitlement contracts, production seller protection and approved refund windows remain outstanding with the named decision owners.

Local demo payment confirmation remains an authenticated **demo action**. With a test secret key configured, new orders use Stripe-hosted Checkout, and payment confirmation comes only from authenticated server retrieval of Stripe session state. PixUP never receives card details. Bank payouts and carrier shipments remain simulations; item 3 separately enables opt-in Stripe transfers to connected test balances. Simulated refund and payout actions are disabled for Stripe orders. Demo rates are 5% seller commission, $8 optional delivery, 100 credits per dollar, and 500 credits for the initial RePool offer, with staff-authored revised demo offers. Each version records its amount, expiry, author and policy; admission posts exactly the accepted amount. They are intentionally labeled test constants rather than approved business terms.

The API refuses unsupported application modes and refuses an unspecified production mode. A production Next.js build can still be served for local evaluation using `APP_MODE=demo`; this is not permission to operate real-money commerce. A demo-mode flag is an operational guard, not a substitute for production security review.

There is no real tax calculation, bank reconciliation, production PSP reconciliation, consumer shipping protection, regulated custody, insurance, chargeback recovery or validated authentication model. Stripe test-session reconciliation is implemented; it does not establish live-money readiness. Internal balanced journals do not establish external cash availability or physical custody. Platform-owned sales use simplified demonstration accounting; finance must approve the production chart of accounts and revenue treatment.

IFCI payments, royalties, FPCR reserve deductions and VACV valuation are not activated. Creator reports expose versioned observational attribution separately from payables. The price-reference panel uses curated comparable cohorts, separate simulation/reviewed-external lanes and reproducible provisional statistics. Calibration uses synthetic scenarios; market accuracy and commercial valuation approval are not established.

## Production increment 2: identity, recovery and access administration

The local identity/access increment is implemented with migration 013. See [setup, recovery, provider acceptance and database roles](identity-and-access.md). Existing accounts are not silently verified, enrolled or promoted; external identity/email providers remain off until configured.

- **Managed identity and email:** OIDC authorization code/PKCE, single-use browser-bound state, nonce and signed-token checks bind users by issuer/subject. Matching emails never auto-link accounts or grant staff roles. A configurable Resend adapter drains encrypted, idempotent email messages. Explicit one-use links verify mailboxes/invitations or reset local passwords; provider acceptance does not prove delivery. Password reset revokes sessions while retaining MFA.
- **MFA and recovery:** Account security adds encrypted authenticator enrollment, replay-resistant codes, hashed one-use recovery codes, protected factor replacement, reauthentication and session revocation. Replacement preserves the original factor until confirmation. Enrolled accounts always require MFA; the staff-enforcement flag additionally requires enrollment. Pending MFA cannot call protected APIs. Privacy export omits secrets; eligible closure destroys factors/recovery material and pending mail.
- **Administrative authority:** verified creator/merchant owners can nominate verified existing members, who must consent within 24 hours. Atomic acceptance preserves item title/payees and revokes both users’ sessions. A separately bootstrapped `identity_admin` permission and fresh MFA govern independent, immutable staff-access reviews. Current authority and exact prior permissions are rechecked; changes revoke target sessions and protect administrator quorum. No seeded account receives identity administration.
- **Database defense in depth:** optional hardened PostgreSQL startup separates migration, API and worker credentials and rejects unsafe roles/privileges. Initial RLS policies cover private collection rows, addressed invitations and ownership proposals. Authenticated actor context is transaction-local and reset across pooled connections/rollback; workers use a separate named role. Full financial/evidence/authentication-table policies and separately deployed workers remain outstanding.
- **Acceptance limits:** signed OIDC transport fixtures and capturing mail fixtures exercise contracts; no hosted IdP or email domain was configured and no external email was sent. Account linking, provider deprovisioning, delivery/bounce evidence, loss of all authentication factors, deployed key operations and broader tenant-policy coverage remain launch work. Registry access timed out; pinned official GitHub release packages installed successfully. The dependency advisory assessment is unavailable, not passed.
