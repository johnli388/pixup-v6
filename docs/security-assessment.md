# Local pilot security assessment

Assessed October 30, 2026 for production increment 7. This is a source review and executable local control assessment, not an independent penetration test or approval for external paid commerce. Application mode remains `demo`; Stripe live keys remain rejected.

The review uses [OWASP ASVS 5](https://owasp.org/projects/asvs) as a control reference, including its [security logging and error handling requirements](https://github.com/OWASP/ASVS/blob/master/5.0/en/0x25-V16-Security-Logging-and-Error-Handling.md). It does not claim complete ASVS coverage or certification.

## Scope and trust boundaries

Reviewed the browser/Next proxy, Express API, account and organization authorization, shared transaction/channel core, signed provider/device entry points, PostgreSQL persistence, background workers and new administrative scripts. Assets at risk include credentials, addresses, private artwork/evidence, exclusive physical stock, payment instructions, credit balances, provenance, and backup contents.

Primary threats are cross-account access, stale authorization, CSRF/XSS, credential guessing, forged or replayed provider/device events, competing stock claims, duplicated financial transitions, sensitive logging, incomplete restriction/erasure, unobserved worker failure and unusable backups. Automated checks cover these specific paths; they do not enumerate every endpoint or substitute for an adversarial review.

## Privacy review

Migration 008 does **not** invent consent for existing accounts. Only newly generated synthetic demo fixtures receive explicitly labeled fixture declarations. Existing users must review Account settings before new commerce. Negative age declarations remain restricted until another support reviewer records a review, after which a fresh declaration is required. Raising `PILOT_MINIMUM_AGE` invalidates declarations below the new threshold.

Restriction or deletion requests stop new commercial activity, withdraw ordinary active listings, revoke the user's tool credentials and disable marketing. Already-created payments, refunds, custody recovery and support remain available. Active channel stock retains its physical recovery holds; restricted sellers cannot obtain new checkout quotes or reservations.

The self-service export explicitly covers account identity, declaration history, owned stock, orders, credits and privacy requests. Seller exports omit buyer addresses and exports exclude authentication/provider secrets. Other records require support-assisted review and third-party redaction. This is not a complete statutory access-response system.

Support may close a low-history account only when checks find no business, custody, support, remaining-credit or shared-owner retention dependencies. Closure pseudonymizes identity and invitations, removes sessions/private uploads/personal activity/memberships and revokes keys. Immutable audit, consent and financial/provenance records are preserved. Accounts with retained dependencies remain open for a documented retention decision. Privacy request notes and immutable history can contain personal information: this is selective pseudonymization, not comprehensive erasure. Rejection/completion of a restriction request does not silently restore access.

## Release disposition

Local controls and exercises are implemented. External paid-pilot approval remains blocked on the documented deployment requirements, an available dependency assessment with findings resolved, and independent security review. The repository cannot establish operational ownership, approved retention/age policy, real receiver delivery, key custody or disaster recovery for infrastructure that has not been deployed. See the [runbook](operational-readiness.md) for reproducible checks and the evidence retained in this repository.
