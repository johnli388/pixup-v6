# Cross-feature code review — October 30, 2026

Reviewed the accumulated implementation at its integration boundaries: publishing and public catalog visibility, identity/session and workspace authorization, transaction recovery and commercial approvals, channel allocation and scoped tools, evidence access, migration/runtime roles, and CI/restore verification. Existing demo economics, the 18+ baseline and external-provider defaults are preserved.

## Findings fixed

| Priority | Finding                                                                                                                                                                                                                       | Correction                                                                                                                                                                                                                                                                                                                                     |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P1       | Individual listing and checkout could bypass collection publication. A PostgreSQL policy-hidden parent also became a null collection in public catalog/tool left joins, which incorrectly passed the “no collection” branch.  | Shared predicates test the asset's actual collection foreign key and require a published parent. Listing, channel allocation, quote, checkout and payment completion enforce publication. Public item, artwork, certificate, saved-item and channel views retain the same boundary; authorized owner/workspace/staff access remains available. |
| P1       | Open provider reconciliation exceptions and signed dispute events awaiting processing blocked some funds operations but did not consistently stop stock movement, resale or tool routing. Separate hold queries had diverged. | One asset-level hold predicate now covers full/partial refunds, disputes, pending transfers, reconciliation exceptions and queued dispute events. Physical movement, resale, channel allocation, payment completion and new tool results use it. Resolving a hold restores the existing workflow without rewriting prior orders.               |
| P2       | Saved-item responses returned other owners' user IDs and delegated inventory workspace IDs, and could retain access after stock became private.                                                                               | Saved results recheck current visibility and omit those identifiers. Users can still remove their own saved reference after access is lost.                                                                                                                                                                                                    |
| P2       | CI ran restore/load verification but did not run the separate migration/recovery/runtime-role suite. Its disposable LOGIN roles also assumed trust authentication.                                                            | CI now creates a separate empty recovery database and runs the PostgreSQL suite. Test roles receive distinct generated passwords, kept out of logs. The harness was verified against a disposable SCRAM-authenticated PostgreSQL instance.                                                                                                     |

The shared predicates are in [catalog visibility](../packages/domain/catalog-visibility.ts) and [inventory holds](../packages/domain/inventory-holds.ts). Public channel filtering preserves the original GOUP allocation count and slot index when computing shipping shares, so hiding private stock does not silently redistribute its shipping charge to another participant.

## Verification

- Five new regression cases reproduced failures before the corrections. A sixth verifies private channel-stock filtering and unchanged GOUP shipping shares.
- **139 backend tests passed** in the final full run, including publishing, holds, recovery, identity, payment, evidence and channel suites.
- **23 browser journeys passed**, including saved-item behavior, web and channel purchase, finance workflows, identity recovery and permission revocation.
- **Production build passed**; the final TypeScript check also passed after the added channel regression and response typing adjustment.
- **PostgreSQL 18 migration/recovery/role checks passed**, including actual row-policy-hidden collection parents, public catalog/tool denial, private owner access and generated LOGIN credentials under SCRAM authentication.
- `git diff --check` passed. Verification used temporary databases and local test servers. `.env` and application data were not modified. No new migration is required; the schema remains at 014.

The GitHub workflow itself was updated but was not remotely dispatched. Hosted provider acceptance, production commercial decisions, broader tenant-table policies and the previously unavailable dependency advisory assessment remain as documented in [implementation status](implementation-status.md); this code review does not establish those approvals or validations.
